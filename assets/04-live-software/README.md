# 第 04 章当前主线资产

## A/B 平台的测量条件

四个入口统一要求第二章的新 A/B 平台，测量期间固定 `MULTICAST_A`、关闭 B 路，结束时恢复原模式。`software.market.json` 记录原模式、测量模式与恢复结果，并纳入本轮 SHA 清单；恢复失败返回 125。它不替代成交、行情完整性或性能检查。

旧平台没有新 schema 时，入口会停止并提示升级。先运行第二章的 `01-restore-trading-lab.sh --upgrade-ab`；随后从本章运行 ① 重新建立比较基线。下文既有测量数值及 RUN 仍为旧版本历史结果，不能混入新 A 路条件的比较。

本目录不依赖监控服务，直接读取第 02 章的 `02-trading-baseline.env`。

本目录只操作第 02 章已经在线的 Trading Lab：比较 MANUAL C++ 的队列存储、同步等待与 CPU 位置，终端直接显示结果。行情回放和 AUTO 策略继续；测量脚本另以约 10 Hz 向 AUTO 提交对照单。正文内联四段 shell 必须与本目录逐字一致，并用 `# ~~~~~……~~~~~` 分段。

| 文件 | 唯一变量 |
| --- | --- |
| `01-measure-deque-cv.sh` | `DEQUE_CV/dedicated` 连续复测 8 轮 |
| `02-measure-fixed-cv.sh` | `DEQUE↔FIXED` 按 `ABBA→BAAB` 配平，只换储存 |
| `03-measure-spsc-spin.sh` | `FIXED↔SPSC` 配平，将互斥锁与 CV 唤醒整体换成 SPSC 原子操作与忙轮询 |
| `04-measure-spsc-shared-cpu.sh` | SPSC 不变，只把 MANUAL order thread 从隔离 CPU 2 移到共享 CPU 0；退出时自动恢复 |

每个 profile 重复 8 轮。MANUAL 每轮 40 warmup + 400 measured、20 ms 间隔（50 Hz）；AUTO 每 5 个 MANUAL 节拍随行一笔，即 8 + 80（10 Hz）。每个 arm 合并 3200 个 MANUAL measured 做 p99 bootstrap，另合并 640 个 AUTO measured 做 p50 环境门。

CPU 角色冻结为 MANUAL order=2、AUTO order=3、普通 housekeeping=0–1；共享核卡把 housekeeping 与 MANUAL order 都固定到 CPU 0。SPSC 使用真忙轮询，必须有隔离核。测量订单在每个 phase 前按当前持仓选择安全首单，随后买卖交替，这批测量单带来的净仓位变化为 0；AUTO 原策略可能另行改变持仓，真实风控不关闭。

## 样本有效性检查

以下是本课脚本自动执行的固定检查。正文只要求先读“这一轮能不能用”，再解读 MANUAL 的交棒与整段耗时；本表供教师核对实现，不是额外操作步骤。

MANUAL 用交接段 P99 判断配置之间是否有稳定快慢差异；AUTO 用往返 P50 检查环境变化是否在允许范围内。两者的指标和用途不同，不能用同一个“相差几微秒”的门槛判断；MANUAL 的快慢统计另见[课堂输出与原始统计](#课堂输出与原始统计)。

| 检查项 | 适用范围 | 固定门限 |
| --- | --- | --- |
| AUTO 每轮稳定性 | 所有实验 | 前、后半窗往返 p50 变化不超过 20% |
| 单配置基线稳定性 | 建立基线时 | 8 轮交棒 p99 的最大值 / 最小值不超过 1.50 |
| 相邻对比的方向一致性 | 比较两种配置，且已检出交棒差异时 | 8 对中至少 7 对支持同一快慢方向，即 87.5%；未检出交棒差异时不应用此项 |
| AUTO 两组环境可比性 | 比较两种配置时 | 两组 AUTO 往返 p50 差值的整个 95% 可信范围须落在基础容差内；容差为两组 p50 较小值的 ±40% |

在基础容差内，还要判断环境变化的方向：若 AUTO 未检出差异，或检出的差异不利于交棒较快的一组，可保留比较；若有利于交棒较快的一组，AUTO 差值的绝对值不得超过交棒差值绝对值的一半。若交棒未分出快慢、AUTO 却检出差异，也不采纳这次比较。

任一道门失败仍保留 raw 并输出 `REJECTED_*`，不得事后放宽阈值追 PASS。实现见 [software_measurement.py](../../apps/flle-trading-lab/tests/software_measurement.py) 的 `control_half_drift`、`directional_environment_gate`、`paired_direction_gate` 及单配置轮间比值检查。

## 课堂输出与原始统计

课堂输出分开显示样本读数与最终结论：先读“这一轮能不能用”，再读交棒和整段的“结论”。通过全部检查后，才可显示某套更快或暂时分不出快慢；未通过时，两项结论均显示“本批检查未通过，不能判断谁更快”。AUTO只报告本项对照检查是否通过，不能代替整批检查。

原始 `software.csv`、`software.summary.json` 仍保留全部样本、统计范围及判定码，计算方法和门限未因简化输出而改变。`difference_ns` 是前一套耗时减去后一套耗时；`ci95` 是重采样得到的95%差值区间。区间包含0时，单凭本批统计不足以支持快慢方向；区间不含0也仍须通过整批有效性检查。课堂正文不展开正负号和区间计算。

正文注明RUN的输出是历史数据经当前显示函数生成的阅读副本；原始RUN日志不改。运行①旧摘要缺少的三项AUTO p99从同RUN的正式样本CSV复算后补入内存中的显示数据，不回写旧摘要。显示回归入口为 `python3 -B apps/flle-trading-lab/tests/test_software_measurement_output.py`，从仓库根执行，不连接设备。

## 历史复测记录

以下保留早期重复实验的原记录，用于核对结论范围，不参与当前四张执行卡的顺序。当前正文以各卡注明的历史 RUN 演示读数，重刷结果单独判断。

这不是运气好碰上的一次。同一条热路径另外做过 5 次独立复测，5 次都是盯着看更快，每次 8 对相邻轮次也都指向同一边：

| RUN | 睡着叫醒 交棒 p99 | 盯着看 交棒 p99 | 快了几倍 | 相邻方向 |
|---|---:|---:|---:|---:|
| `155323Z` | 17977 ns | 6977 ns | 2.58× | 8/8 |
| `155727Z` | 17758 ns | 6801 ns | 2.61× | 8/8 |
| `160132Z` | 17342 ns | 6941 ns | 2.50× | 8/8 |
| `160547Z` | 16997 ns | 6815 ns | 2.49× | 8/8 |
| `160952Z` | 16555 ns | 6185 ns | 2.68× | 8/8 |

这个对比在正式 RUN 之前也复测过六次。六次的数字都指向同一边——挤在杂活核更慢——但相邻轮次的一致程度分三档：

| RUN | 这一轮能不能用 | 相邻方向 |
|---|---|---:|
| `162028Z` | 不能用：相邻方向不一致 | 6/8 |
| `162448Z / 162910Z` | 能用 | 7/8、7/8 |
| `163350Z / 163815Z / 164239Z` | 能用 | 8/8、8/8、8/8 |

最后三次里，挤在杂活核的交棒 p99 是 `64.5 / 57.1 / 61.0 µs`，独占座位是 `6.6 / 7.0 / 6.6 µs`；带自动恢复的正式 RUN `170545Z` 同样是 8/8。第一次那份「不能用」也一并留着：从六次里挑三次好看的报，就不叫测量了。
