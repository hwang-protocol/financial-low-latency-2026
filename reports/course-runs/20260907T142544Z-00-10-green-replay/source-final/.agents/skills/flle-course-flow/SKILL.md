# 让读者沿着任务读下去

适用于本仓库课程，保留用户指定的主题、案例和操作界面。先完成 [AGENTS 恢复流程](../../../AGENTS.md)，再按 [写作硬规则](../../../Documents/00.WRITING-HARD-RULES.md)处理内容；本 skill 补充阅读判断，不复制格式规范。

默认处理正文顺序、解释和必要排版。发现源码、图形或实测证据问题时，先核实它是否属于本次任务；按已授权范围分别遵循硬规则 §6、§3.3.3、AGENTS 运行态与事实登记纪律。顺稿本身不授权改运行源码、改图字节、运行实验或提升验证状态，也不扩展到用户尚未要求的章节。

仓库 `.agents/skills/flle-course-flow/` 是唯一权威源，AGENTS 提供项目入口。Codex 使用本机 `~/.codex/skills/flle-course-flow` 链接；Cursor 使用仓库 `.cursor/skills/flle-course-flow` 相对链接。两者都指向此处，不维护第二份内容；链接可读不等于已验证编辑器每次都会自动触发。

## 先理顺整章，再修句子

完整读正文、现有图中文字、相关代码和用户评估。用一句话确定读者本章要完成什么，再列出实现它必经的几步。逐节检查：上一步已经解决什么；此时还有什么问题；本节解决后才能做什么。连接句表达真实依赖，不能只补“接下来”“此外”。

开场先用具体问题或任务建立目的，必要定义与官方来源随后就近引入，顺序遵循硬规则 §3.1。标题点出动作或问题，避免用分类编号代替阅读目的。原理为操作铺垫，验证回答原理提出的问题；与当前任务无关的跨章状态和内部维护细节放配套资料，留下入口。

跨章课程先确定稳定的应用基线：首次部署时备齐后续需要的业务能力，后面逐章改变测试条件。写清“程序版本不变”和“运行配置可切换”的区别；不要把开发时分批加功能的过程照搬成学员反复升级系统的课程顺序。所谓“一次到位”，要以学员当场能使用相应功能验收；不能只凭文件已复制或按钮已显示。需要独占资源才能启用的功能，在初次部署处交代切换入口。

## 课堂操作要能停下来讲

按可观察的阶段划分课堂操作：先准备并确认正常状态，再主动改变一个条件，随后核对效果，最后恢复。每步结束后让老师决定何时继续；不把几个标题放在同一个自动跑到底的脚本上充当分步。

每个阶段都写清执行入口、可观察的结果和停顿点，正文必须与实际脚本一致。正常讲解多久都不应触发恢复；动作失败或单条命令超时才属于异常。短有效期的操作应在同一步内完成触发，再保留现场供讲解。

锁、进程身份、状态接续和恢复的实现示例见[第10章教师说明](../../../Documents/newDoc/assets/09-verilator/TEACHER-LIVE-NOTES.md#分步课堂运行)。只有任务明确包含脚本修改时才处理这些实现，普通顺稿不要求重审或改造运行代码。

把耗时准备与教学动作分开：大包下载、完整依赖备齐和不参与讲解的重构建放课前，在保留的 `.111` 缓存并校验。绿色卡片使用本地制品；不能把公网慢下载藏进一个“准备”入口。保留必要的教学编译与正式采样，并说明实测耗时。实现与缓存清单见 [artifact vault](../../../artifacts/README.md)。

## 什么时候需要解释

读者需要某个概念才能理解下一步时，在首次使用处说明“它是什么、谁产生、交给谁、改变什么”。一两句能解决时，不另建术语长表。

- 问“什么语言/这是命令吗”：区分源码、工具、生成文件、运行对象和硬件，点明所在文件与执行者。
- 问“怎么又有一个程序”：分开构建时与运行时，说明几份源码、几个可执行文件、几个进程。
- 问“启动什么/发令怎么发”：补齐动作对象、入口、信息载体、读取者与状态变化。
- 被多个相似数值绕晕：按职责和归属比较，解释变化条件，不把不同状态混成一个开关。
- 问“复制到这里干什么”：说明源文件、目标位置和下一条命令之间的关系。
- 问“快不快”：区分功能正确与性能证据，不能从工具或硬件名称直接推出实测结论。

删除不参与本段理解的变量；必要的英文名紧跟中文含义，后文沿用同一称呼。不要为了少写一句而混淆职责，或借简化改变技术事实。

## 什么时候需要画图

单个概念优先用短文或小表。多个角色、不同路径、时间先后、状态归属，尤其解释后读者仍问“谁给谁/到底经过谁”，适合用图。先检查能否调整现有图的说明或位置；确需修改图时，再按任务范围处理。

每张图回答一个明确问题。总览、内部机制、操作过程、结果核对各有用途，不堆重复总图。把图放在展开解释之前，再按图的阅读顺序讲：

- 角色关系：谁发送、谁接收、状态由谁保存。
- 路径关系：数据与控制分别传什么，原始数据与副本是否不同。
- 时间关系：哪个事件推进处理，状态如何从前值变成后值。
- 操作关系：输入命令怎样产生文件或改变状态，下一步读什么。

箭头形状、尺寸、框外间隙与审图要求统一引用硬规则 §3.3.3，不在技能里维护另一套参数。

## 命令与结果怎样连续讲

保持用户要求的操作界面，脚本内部语言放配套工程说明。每步交代必要的执行位置、输入、产物或状态变化，再给返回及读法。文件名不单独冒充命令；命令没有终端输出时，说明它实际写了文件还是改变了状态。

区分“给读者解释命令”和“要求读者现在执行”，也区分真实命令、模拟场景和未实现的教学接口。输出应来自声明的证据来源，不能用模拟查询或模拟抓包证明现场成功。卡片语义与颜色遵循硬规则 §7.1、§7.3；HTML/Markdown 边界和实际解析检查遵循 §7.5。

## 第十章的应用例子

这些是方法示例，不是其他章节必须套用的目录或术语：

- 任务顺序：认出 NVDA → 只允许丢一次 → 分步准备、发令、核对、恢复 → 转向真卡。
- 对象归属：两类 C++ 代码编成一个程序，其中模型由 RTL 生成，手写代码收发原始报文。
- 信号区别：valid 表示有消息，ready 表示能接收，时钟沿规定保存状态的时刻，额度表示剩余次数；不能把组合信号也写成只在时钟沿变化。
- 文件去向：复制 `.sv` 为构建提供源码；复制 `.bit` 方便后续装载引用；`printf ... > 文件` 把文字写入控制文件，由已运行的程序检查读取。

## 完成前的读者顺序检查

按正文顺序检查，不靠自己知道的源码补全作者省略的环节：

- [ ] 开场两段内能找到具体任务，学习目标与本章实际讲授范围一致。
- [ ] 理解当前步骤必需的首次名词已解释；无关变量已移出，同一对象称呼一致。
- [ ] “它/这里/启动”等指向唯一；动作的执行者、输入和状态归属明确。
- [ ] 每节承接上一步未解决的问题，产物与下一步用途相连。
- [ ] 课堂阶段有独立入口、观察结果和停顿点，不把正常讲解停顿算作执行超时。
- [ ] 图先于展开解释，每张图回答不同问题，图中文字与正文和源码一致；换图后同步图卡、alt 和资产用途。
- [ ] 命令/代码/输出身份明确，展示结果属于同一已核验 RUN，展示的输出行必须是现役入口实际会打印的行；需跨 RUN 对比时分别标注，未实测内容保持模拟或设计身份。
- [ ] 正文不穿插维护过程叙述；验证状态由治理文件和教师说明管理，并与所述代码版本、实际证据一致；影响结论的证据范围和待验证项在学生正文保留简短说明。
- [ ] 理解检查只考正文讲过的内容；不服务当前任务的跨章状态与维护细节有配套入口。
- [ ] 搬移后重读原位置与新位置：学习目标仍有正文支撑，导航卡内不混入正文，标题/任务地图/当前标签相符；标签闭合检查不能代替内容归属检查。
- [ ] 运行与改动相称的格式/卡片/链接/语法检查，核对授权范围，并按仓库规则登记变更与验证限制。

评估是线索，不自动是事实。偏移、长度、更新条件回源代码或第一手规范；归档核验不等于本轮实跑。交付说明阅读顺序如何改变、验证了什么、还有什么未实测。
