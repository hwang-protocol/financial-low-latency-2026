# 金融低延迟工程实验课：从一条行情到一笔订单

行情到了，程序什么时候看到？订单发出后，多久得到成交回执？链路没有丢包，为什么偶尔还是很慢？本课沿一套持续运行的交易系统回答这些问题：**先把路径接通，再读懂消息、量清耗时，最后逐层改变处理方式。**

面向已有 Linux 和网络基础的工程师。金融协议、软件机制和硬件术语在第一次需要时解释；不要求先会写 C++、P4 或硬件代码。课堂使用 Nasdaq 历史行情与实验室纸面撮合，研究收发、测量和恢复，不涉及真实资金交易。

## 先认识这套系统

把它想成两间通过快递站相连的办公室：一边发布市场消息，另一边据此提出订单；订单送回后，还要等明确回执。

<img src="images/course-visuals/03-diagrams/03-message-and-receipt.svg" alt="行情从 Exchange 发往 AUTO 与 MANUAL；两种客户端各自通过独立订单连接接收回执" style="display:block;width:100%;max-width:800px;height:auto;margin:14px auto;">

| 对象 | 在课程里做什么 |
| --- | --- |
| Exchange（交易所程序，`.1`） | 重放历史行情，接收订单并做纸面撮合 |
| Trader（交易客户端，`.2`） | 接收行情、维护订单簿，发送订单并处理回执 |
| AUTO / MANUAL | `.2` 上两个独立客户端：一个按教学策略发单，一个承接网页或测量脚本的订单 |
| 7150 交换机 | 连接两端，转发报文；后面观察它的出口队列与时间戳 |
| 管理与观测工具 | 负责启动、发指令、读日志和看图表；管理连接与被测交易链路分开 |

**“已接收订单”与“订单已成交”是两件事。** 这条区别从第二章第一笔交易一直保留到最后；优化速度和过滤消息，都不能破坏原有业务含义。

## 一节课怎样讲

每节先提出一个问题，用图和必要的概念解释机制，再执行操作、读取关键结果。无需逐字读完脚本；先说清在哪台机器执行、会改变什么，以及完成后看哪几行。

1. **先看正常状态。** 确认系统能工作，知道原来是什么样。
2. **再改变一个条件。** 例如换等待方式，或给过滤程序一次丢包额度。
3. **停下来读结果。** 看被改动的部分，再看下游是否出现对应现象。
4. **恢复并确认。** 回到下一节需要的状态，以业务结果核对恢复。

有独立阶段入口的实验，可以一张卡一张卡讲。脚本若自动完成多个动作，正文会说明执行范围和输出顺序；脚本内部的几个标题不等于可以手工停步。第九、十章的正常讲解停顿不触发恢复；单条命令的执行时限仍用于识别卡住或失败。

绿色执行卡是当前步骤的入口。代码节选用于解释实现；“命令（模拟）”“模拟输出”属于硬件教学情境，不能当作本课已经装卡成功的证据。命令写文件而没有屏幕输出时，要接着看哪个程序读取它、状态怎样变化。

## 图和数字怎样读

每张图先找对象和边界：哪个程序收发，哪个程序只做判断，状态保存在哪里；实线、虚线的含义以该图说明为准。图标帮助认角色，箭头说明关系，不能靠颜色猜功能。

看到输出时，依次问：

- 来自哪台机器、哪个接口、哪一次记录？
- 显示的是配置、状态、累计计数，还是逐笔样本？
- 它与上一步改变的条件有什么对应关系？
- 功能正常、性能改善和恢复完成，分别有什么证据？

正文中的历史结果用于练习读法，重跑后的序号、文件路径和时间会变化。`PASS` 表示满足该步骤的检查条件，不代表所有路径都更快。模拟成功示例也不会升级为现场实测。

## 建议授课节奏

| 单元 | 章节 | 讲解 | 实验 | 当堂产出 |
| --- | --- | ---: | ---: | --- |
| 计算机与物理路径 | 00–01 | 3 小时 | 2 小时 | 手画从程序到网卡、交换机再到程序的路径 |
| 交易基线与报文 | 02–03 | 3 小时 | 3 小时 | 完成交易，从报文解释行情与回执 |

合计建议 18 小时讲解、17 小时实验。短训可以选讲，但要保留所选实验的前置步骤、结果核对和恢复；不要从中间的执行卡直接开始。

## 怎样判断学会了

| 验收 | 分值 | 检查方式 |
| --- | ---: | --- |
| 章节理解检查 | 45 | 从第 00–10 章实际题目中选题，先按所选题数归一，再折算；看职责、路径和因果是否讲清 |
| 手画交易路径 | 20 | 画出两端程序、网卡、交换机，标明行情、订单与回执方向 |
| 给定故障选择证据 | 20 | 面对“链路通但应用没消息”或“偶尔卡顿”，能选对日志、计数、抓包和时间样本 |
| 恢复与解释结果 | 15 | 能确认资源归还、业务恢复，并说明当前结果适用的范围 |

70 分表示能在提示下完成实验并解释主线；80 分表示能独立选择大部分证据；90 分表示能提出公平的对比实验，识别错误推断并安排恢复。分数是课堂自评，不代表具备完整生产交易系统的设计资格。

教师课前恢复、构建归档和历史验证状态集中在[课程配套说明](TEACHER-FLOW-NOTES.md)，现役事实以 [PINS](../00.PINS.md) 和 [FREEZE-LEDGER](../00.FREEZE-LEDGER.md) 为准。学生从[第 00 章](00-cpu-cache-memory-os-basics.md)开始，每章先回答理解检查，再进入下一章。
