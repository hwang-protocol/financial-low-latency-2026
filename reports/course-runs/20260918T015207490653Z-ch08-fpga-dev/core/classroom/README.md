# 第08章逐卡操作入口与第08—09章共享开发环境

全部入口在 `.111` 的 root 终端执行，脚本自动 SSH 到 `.101`；每次只运行选定的一张卡，结束后停下。正文保留单行入口，具体命令见 `remote/` 与 `operations/`。

| 子步骤 | 入口文件 | 在开发机做什么 / 保存什么 |
| --- | --- | --- |
| 1.1 | 1.1-distribute.sh | 新RUN目录、两章源码与离线工具，安装共享Verilator/g++/make |
| 1.2 | 1.2-check.sh | 自动查主机、系统、架构和分发材料 |
| 1.3 | 1.3-install.sh | 安装Icarus、独立Python/Yosys环境，核对两章工具 |
| 3.1 | 3.1-compile.sh | filter.vvp、编译日志和摘要 |
| 3.2 | 3.2-simulate.sh | 22帧仿真日志 |
| 3.3 | 3.3-management.sh | 16项管理测试日志 |
| 3.4 | 3.4-synthesize.sh | 过滤通用网表与日志 |
| 3.5 | 3.5-synthesize-registers.sh | 寄存器通用网表与日志 |
| 3.6（选做） | 3.6-collect.sh | 另存完整work归档，状态COLLECTED；重做无需先归档 |

`stage-runner.py` 负责执行位置检查、读取 `.111` 的 `reports/run-state/ch08-fpga-dev.env`、调用单步脚本和留存结果。远端脚本通过SSH标准输入发送，显式传入本轮 `dev.env`；不依赖人工登录或旧终端变量。

每次调用在 `.111` 本轮结果目录创建 `steps/时间-步骤/`，保存 `classroom.log`、执行脚本副本、`receipt.json` 与 `SHA256SUMS`。1.2/1.3/3.1—3.5另收回累计 `work/` 为 `remote-work.tgz`；该目录可能包含前序产物，必须结合本次退出码和对应日志判断，不能因归档存在就认定本步成功。长输出完整保留，课堂显示实际tail/grep节选。失败仍保存终端错误并尝试收回工作目录；前置检查失败则写入 `reports/ch08-entry-errors/`。

维护核验可设置 `FLLE_CH08_STATE` 为单独的运行态路径：新RUN保存在此路径，且不覆盖 `.101/current.env`。正常课堂不要设置该变量。核验索引见 `Documents/design/evidence/ch08-auto-ssh-and-deployment-focus-20260918.json`（仓库根目录起算）。

第08—09章共用这一次准备好的 `.101`，第09章直接读取 `/opt/flle-ch08-dev/current.env`：

- `FLLE_CORE=$FLLE_DEV/core`：第08章的源码副本，原路径和后续命令不变。
- `CH09_SRC=$FLLE_DEV/ch09`：整个 `09-verilator` 目录的副本，第09章从这里阅读源码、编译和本地测试。
- `FLLE_DEV/tools` 和 `FLLE_DEV/venv`：第08章的离线安装材料与独立 Python 工具。

`1.1` 在 `.111` 调用公共离线安装器，将既有 `verilator` profile 安装到 `.101`；该 profile 固定 Verilator 4.038、g++、make 及依赖，共63个包、约79 MB。安装器先核对 `.111` 缓存摘要与 `.101` 系统/版本，再经管理网分发，安装时不访问公网；版本齐全时跳过安装。安装日志单独保存在 `.111` 本轮结果目录的 `verilator-install.log`，不放进 `inputs.tgz`。第08章原有约29 MB的 Icarus/Python 缓存仍单独校验；不合并或重新打制缓存。

两章源码的上游原件仍在 `.111` 仓库，`.101` 的副本用于开发。第09章涉及 `.2` 交易客户端的现场操作仍由该章指定入口执行；把源码复制到 `.101` 不会自动改变交易环境。第08章结束后，若紧接着学习第09章，保留这份 `.101` 环境；重做时直接恢复快照并从1.1开始，无需先完成3.6。

任何命令失败均停止当前脚本，不继续跳步；tee保留原命令失败状态。编译/综合重跑会替换本轮对应输出；每次1.1创建全新目录。3.6只收回文件，不能用COLLECTED替代仿真/综合结果。安装不创建常驻服务，实验不控制数据网口或现役交易程序。

快照基线、缓存恢复方法与每步说明见正文。`.111`上的离线缓存由校验清单保护，Git只保存清单；不要删除缓存后声称仅凭源码仓库能够离线开课。用户需要从头重做时，直接自行恢复`.101`快照并从1.1开始；连续学习第九章时保留环境，本文不会操作虚拟化平台。
